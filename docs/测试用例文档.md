## 6. 缺陷记录与回归（重点）

本项目在开发过程中发现并修复了 3 个典型缺陷，均已回归验证通过。

### 缺陷 #1：更换知识库后 Agent 不检索新文档

| 项 | 内容 |
|---|---|
| 严重程度 | 高 |
| 现象 | 上传大数据知识库后，问大数据问题，Agent 凭记忆作答而非检索新文档 |
| 根因 | 系统提示词与工具描述中写死旧主题「股票、投资、财务指标」，Agent 误判新主题「不相关」而跳过检索 |
| 修复 | 移除写死的领域描述，改为「知识库主题动态变化，以实际导入文档为准」 |
| 回归 | 问大数据 4V，正确带 [资料N] 引用（通过） |

**经验教训**：Agent 的系统提示/工具描述不应写死业务领域，检索策略须与领域预设解耦。

### 缺陷 #2：中文查询检索不到目标文档

| 项 | 内容 |
|---|---|
| 严重程度 | 高 |
| 现象 | 问「小个子显高的搭配思路」，召回的全是股票/大数据块，穿搭块一个都不中 |
| 根因 | 中文关键词提取逻辑「去停用字后整段拼接」，把「小个子显高的搭配思路」粘成无意义的「小子显高搭配路」，无法字面命中 |
| 修复 | 改用中文 n-gram（二元组+三元组）滑动切词，切出「显高」「搭配」等实义词；检索排序改为「关键词命中数优先」 |
| 回归 | 穿搭问题 6 块中 5 块来自穿搭文档（通过） |

**经验教训**：中文分词不能靠「去停用字拼接」；多领域混库时纯向量相似度易被噪音稀释，关键词字面命中更可靠。

### 缺陷 #3：来源文件名显示为临时文件名

| 项 | 内容 |
|---|---|
| 严重程度 | 低 |
| 现象 | 引用来源显示 `tmpXXXX.md` 而非真实文件名 |
| 根因 | ingest 接口将上传文件存为临时文件后入库，source 元数据记为临时文件名 |
| 修复 | 入库后将 chunk 的 source 元数据改回用户上传的真实文件名 |
| 回归 | 来源正确显示 `stock.md`、`bigdata_knowledge_base.md`（通过） |

## 附录：手动测试命令速查

```bash
# 启动后端
python -m uvicorn app.api:app --host 127.0.0.1 --port 8000

# 健康检查
curl http://127.0.0.1:8000/api/health

# 对话测试
curl -X POST http://127.0.0.1:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"大数据的4V是什么","history":[]}'

# 清空知识库
curl -X POST http://127.0.0.1:8000/api/reset
```
