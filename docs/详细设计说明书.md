## 2. 模块详细设计

### 2.1 网络兼容模块（app/network.py）

**设计目的**：解决部分网络环境（校园网/家庭宽带）下 DNS 优先返回 IPv6、但本机 IPv6 不通导致的 `getaddrinfo failed` / `ConnectError`。

**实现机制**：模块导入时 monkeypatch `socket.getaddrinfo`，将解析结果按地址族重排，使 IPv4（`AF_INET`）排在 IPv6（`AF_INET6`）之前。

**伪代码**：

```
function _prefer_ipv4():
    if not socket.has_ipv6: return
    orig = socket.getaddrinfo
    function patched(args...):
        results = orig(args...)
        return sorted(results, key=lambda r: 0 if r.family == AF_INET else 1)
    socket.getaddrinfo = patched   // 打补丁失败则静默降级
```

**异常处理**：打补丁全程 try/except 包裹，失败不影响主流程。

### 2.2 文档加载模块（app/loader.py）

#### 2.2.1 加载器映射

```python
LOADER_MAP = {
    ".txt": TextLoader,
    ".md":  TextLoader,
    ".pdf": PyPDFLoader,
    ".docx": Docx2txtLoader,
}
```

#### 2.2.2 加载流程

```
load_documents(file_path):
    path = Path(file_path)
    if not path.exists(): raise FileNotFoundError
    suffix = path.suffix.lower()
    loader_cls = LOADER_MAP.get(suffix)
    if loader_cls is None: raise ValueError("不支持的文件类型")
    docs = loader_cls(path).load()
    for doc in docs: doc.metadata["source"] = path.name   // 溯源
    return docs
```

#### 2.2.3 分块算法

**参数**：`chunk_size=300`，`chunk_overlap=30`。

**切分边界优先级（separators）**：

```
"\n\n"  >  "\n- "  >  "\n"  >  "。"  >  "；"/";"  >  "，"/","  >  " "  >  ""
```

**设计意图**：`"\n- "` 作为高优先级分隔符，保证列表项（如「- ROE 净资产收益率：…」）独立成块，避免多个知识点混入同一 chunk 稀释语义、降低召回率。

#### 2.3.3 混合检索算法（核心）

这是本项目检索质量的关键。纯向量检索对「专业术语/缩写」（如 ROE、PE）和「中文自然语言查询」召回率偏低，故采用**语义检索 + 关键词字面匹配兜底**的混合策略。

**关键词提取（中文 n-gram 切词）**：

```
function extract_keywords(query):
    keywords = 正则提取英文缩写/术语([A-Za-z][A-Za-z0-9+./-]+)
    for seg in 中文连续片段:
        core = 去掉停用字(seg)          // 停用字:怎么什么如何是了的等
        for n in (2, 3):                // bigram + trigram
            for i in range(len(core)-n+1):
                gram = core[i:i+n]
                if gram 不含停用字: keywords.append(gram)
    return 去重(keywords)
```

> **设计要点**：中文无空格分词，不能「去停用字后整段拼接」（会把「小个子显高的搭配思路」粘成无意义的「小子显高搭配路」，导致字面匹配失效）。n-gram 滑动切分可切出「显高」「搭配」等实义词。

**重排与截断**：

```
function search(vector_store, query, top_k=6):
    keywords = extract_keywords(query)
    all_docs = vector_store.similarity_search(query, k=1000)  // 全量取回(演示数据量小)
    ranked = sort(all_docs, key=lambda d: 关键词命中数(d), reverse=True)
    return ranked[:top_k]
```

**排序依据**：关键词命中数（降序），命中数相同时保持语义相似度排序。这样主题词明确的查询能命中正确领域块，而非被多领域混库时的向量噪音稀释。

### 2.4 Agent 工具模块（app/tools.py）

#### 2.4.1 search_knowledge 工具

```python
@tool
def search_knowledge(query: str) -> str:
    docs = search(_get_vector_store(), query, top_k=TOP_K)
    if not docs: return "未检索到相关内容。"
    return "\n\n".join(f"[资料 {i} | 来源: {source}]\n{content}")
```

> **关键约束（工具描述）**：知识库主题动态变化，不预设领域；只要用户问题像在询问「某份资料/知识点」，就应先检索而非凭记忆作答。

#### 2.4.2 calculate 工具

```python
@tool
def calculate(expression: str) -> str:
    if not re.fullmatch(r"[0-9+\-*/().%\s]+", expression):
        return "表达式包含非法字符..."
    result = eval(expression, {"__builtins__": {}}, {})
    return f"计算结果: {expression} = {result}"
```

**安全设计**：正则白名单 + 空 `__builtins__` 字典，杜绝任意代码执行。

#### 2.4.3 工具注册


#### 2.5.2 LLM 与工具绑定

```python
_llm = ChatOpenAI(model=DEEPSEEK_MODEL, api_key=..., base_url=..., temperature=0.3)
       .bind_tools(ALL_TOOLS)   // 自动生成 Function Calling JSON Schema
```

> **踩坑记录**：早期手写 Function Calling 序列化失败（`type` 字段应为 `function` 而非 `tool_call`），改用 `bind_tools` 后由框架统一处理序列化与结果回传。

#### 2.5.3 ReAct 状态机

```
graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)     // Reasoning: LLM 推理
graph.add_node("tools", tool_node)      // Acting: 执行工具
graph.set_entry_point("agent")
graph.add_conditional_edges("agent", should_continue, {"tools":"tools", "end":END})
graph.add_edge("tools", "agent")        // 工具结果回流,继续推理
```

**节点逻辑**：

```
agent_node(state):
    messages = [SystemMessage(SYSTEM_PROMPT)] + state.messages
    ai_message = _llm.invoke(messages)     // 可能带 tool_calls
    return {"messages": [ai_message]}

tool_node(state):
    for tc in last_message.tool_calls:
        output = tool_map[tc.name].invoke(tc.args)   // 异常则返回错误字符串
        results.append(ToolMessage(output, tool_call_id=tc.id))
    return {"messages": results}

should_continue(state):
    return "tools" if last_message.tool_calls else "end"
```

#### 2.5.4 系统提示词要点

- 定义 Agent 能力（检索 + 计算）；
- 明确「知识库主题不固定，以实际导入文档为准，不预设领域」；
- 约束「工具返回未检索到时诚实告知，不编造」；
- 要求基于资料作答时标注 `[资料N]` 引用。

#### 2.5.5 对外接口

```python
def run_agent(user_input, history=None) -> str:
    messages = list(history or []) + [HumanMessage(user_input)]
    final_state = AGENT_GRAPH.invoke({"messages": messages})
```

### 2.6 后端接口模块（app/api.py）

#### 2.6.1 数据模型

```python
class ChatMessage(BaseModel):
    role: str          # "user" | "assistant"
    content: str

class ChatRequest(BaseModel):
    message: str
    history: List[ChatMessage] = []

class ChatResponse(BaseModel):
    answer: str
    error: Optional[str] = None
```

#### 2.6.2 接口详细定义

**① POST /api/chat**

请求体：

```json
{
  "message": "小个子显高的搭配思路是什么",
  "history": [
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ]
}
```

响应体：

```json
{ "answer": "根据知识库... [资料1]", "error": null }
```

**处理流程**：

```
chat(req):
    history = [HumanMessage/AIMessage 转换 req.history]
    answer = run_agent(req.message, history=history)
    return ChatResponse(answer=answer)
```

**② POST /api/ingest**（multipart/form-data，字段 `file`）

响应体：

```json
{ "status": "ok", "filename": "clothing_style_kb.md", "chunks": 12 }
```

**关键修正**：入库后需将 chunk 的 `source` 元数据从临时文件名改回用户上传的真实文件名，保证溯源展示正确。

**③ POST /api/reset** → `{ "status": "ok", "message": "知识库已清空" }`

**④ GET /api/health** → `{ "status": "ok", "service": "ai-rag-agent" }`

## 4. 异常处理设计

| 场景 | 处理方式 |
|---|---|
| 未配置 API Key | 抛 RuntimeError，提示配置步骤 |
| 不支持的文件类型 | 抛 ValueError，返回 400 |
| 文件不存在 | 抛 FileNotFoundError |
| LLM 调用失败 | chat.py 重试 3 次（指数退避），失败回滚历史 |
| 工具执行异常 | tool_node 捕获，返回「工具执行出错：{e}」 |
| 检索无结果 | 返回「未检索到相关内容」，Agent 诚实告知 |
| IPv6 连接失败 | network.py 强制 IPv4 优先 |

---

## 5. 关键算法总结

1. **递归字符分块**：按自然边界优先级切分，保证知识点独立成块；
2. **混合检索**：语义相似度 + 关键词命中数重排（中文 n-gram 切词）；
3. **ReAct 循环**：LLM 推理 ↔ 工具执行的图状态机，条件路由终止；
4. **引用溯源**：检索块带 source 元数据，Prompt 约束模型标注 `[资料N]`。
