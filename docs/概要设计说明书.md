# 概要设计说明书（HLD）

**项目名称**：AI 知识库问答 Agent（ai-rag-agent）
**版本**：V1.0
**日期**：2026-11-16
**文档类型**：概要设计（High-Level Design）

---

## 1. 引言

### 1.1 编写目的

本文档在《软件需求规格说明书》的基础上，描述系统的总体架构、技术选型、模块划分、数据流与接口概要，为详细设计提供框架依据。

### 1.2 设计原则

1. **分层解耦**：表示层、应用层、领域层、数据层职责分离；
2. **演进式架构**：项目按四周迭代（LLM 调用 → RAG → Agent → 产品化），各层可独立替换；
3. **领域无关**：知识库主题不写死，支持任意领域文档。

---

## 2. 总体架构

### 2.1 架构风格

采用 **前后端分离 + 分层架构**：

```
┌─────────────────────────────────────────────────────────┐
│                     表示层（Presentation）                 │
│         Web 前端（HTML/CSS/JS）     命令行（CLI）          │
└────────────────────────┬────────────────────────────────┘
                         │  HTTP / JSON
┌────────────────────────▼────────────────────────────────┐
│                     应用层（Application）                 │
│              FastAPI 后端（api.py）                       │
│       /api/chat  /api/ingest  /api/reset  /api/health     │
└────────────┬───────────────────────────────┬────────────┘
             │                                │
┌────────────▼─────────────┐   ┌──────────────▼───────────┐
│      Agent 编排层         │   │     知识库构建层           │
│   LangGraph ReAct 循环    │   │  文档加载 → 分块 → 向量化  │
│  (agent.py / tools.py)   │   │  (loader.py / vectorstore) │
└────────────┬─────────────┘   └──────────────┬───────────┘
             │                                 │
┌────────────▼─────────────────────────────────▼──────────┐
│                     数据层（Data）                        │
│        Chroma 向量库（本地持久化）                         │
└─────────────────────────────────────────────────────────┘
```

### 2.2 关键设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 前后端 | 原生 HTML/CSS/JS + FastAPI | 轻量、无构建步骤、便于演示与 Docker 部署 |
| Agent 编排 | LangGraph | 图结构可观测、可扩展、支持状态持久化 |
| 工具调用 | DeepSeek Function Calling（bind_tools） | 自动生成 JSON Schema，避免手写序列化兼容问题 |
| 向量库 | Chroma | 轻量本地方案，开发/演示友好，生产可换 Milvus |
| Embedding | 硅基流动 bge-m3 | 中文语义效果好，OpenAI 兼容接口 |
| 检索策略 | 混合检索（语义 + 关键词兜底） | 弥补纯向量检索对专业术语/中文查询的召回不足 |

## 4. 模块划分

### 4.1 模块清单

| 模块 | 文件 | 职责 |
|---|---|---|
| 网络兼容模块 | `app/network.py` | 强制 IPv4 优先，规避 DNS/IPv6 连接问题 |
| 文档加载模块 | `app/loader.py` | 文档解析 + 递归分块 |
| 向量库模块 | `app/vectorstore.py` | Embedding 封装、向量入库、混合检索、清空 |
| RAG 命令行 | `app/rag.py` | 构建带引用 Prompt、RAG 问答 CLI |
| Agent 工具模块 | `app/tools.py` | 定义 search_knowledge / calculate 工具 |
| Agent 编排模块 | `app/agent.py` | LangGraph ReAct 状态图、run_agent 接口 |
| Agent CLI | `app/agent_cli.py` | 交互式 Agent 对话 |
| 后端接口模块 | `app/api.py` | FastAPI 路由，封装 Agent 与知识库能力 |
| 前端界面 | `frontend/` | 网页文档上传 + 对话 |
| 基础聊天 | `app/chat.py` | 第 1 周 LLM 最小验证（命令行流式聊天） |

### 4.2 模块依赖关系

```
api.py ──────► agent.py ──────► tools.py ──────► vectorstore.py
    │                                              │
    └──────► loader.py ──► vectorstore.py ◄────────┘
agent.py ──► rag.py（复用 DEEPSEEK_* 配置与 TOP_K）
所有模块 ──► network.py（导入时自动生效）
```

## 5. 数据流设计

### 5.1 知识库构建数据流

```
用户上传文件
   │
   ▼
api.py /api/ingest
   │  (1) 保存临时文件
   ▼
loader.load_documents()    ──► 解析文档，补充 source 元数据
   │
   ▼
loader.split_documents()   ──► 递归分块（chunk_size=300, overlap=30）
   │
   ▼
vectorstore.create_vector_store() ──► 调用 bge-m3 向量化 → 写入 Chroma
   │
   ▼
持久化至 data/vector_store
```

### 5.2 问答数据流（ReAct 循环）

```
用户提问
   │
   ▼
api.py /api/chat ──► run_agent(query, history)
   │
   ▼
┌─── LangGraph ReAct 循环 ───┐
│  agent_node（LLM 推理）      │
│    │ 有 tool_calls?          │
│    ├── 是 ──► tool_node      │
│    │           │ 执行工具     │
│    │           └─► 返回 agent │
│    └── 否 ──► 输出最终回答    │
└────────────────────────────┘
   │
   ▼
返回 answer（含 [资料N] 引用）
```

## 6. 数据库（向量库）设计

### 6.1 向量库选型

采用 **Chroma** 本地向量库，collection 名为 `knowledge_base`，持久化目录 `data/vector_store`。

### 6.2 数据模型（逻辑视图）

每条记录（chunk）包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID | 唯一标识 |
| document | text | 文本块内容（chunk 正文） |
| embedding | vector(1024) | bge-m3 向量 |
| metadata.source | string | 来源文件名（用于引用溯源） |

## 7. 接口概要设计

### 7.1 HTTP 接口一览

| 方法 | 路径 | 功能 | 请求体 | 响应 |
|---|---|---|---|---|
| GET | `/api/health` | 健康检查 | — | `{status, service}` |
| POST | `/api/chat` | Agent 对话 | `{message, history[]}` | `{answer, error}` |
| POST | `/api/ingest` | 上传建库 | multipart 文件 | `{status, filename, chunks}` |
| POST | `/api/reset` | 清空知识库 | — | `{status, message}` |

（详细字段定义见《详细设计说明书》。）

### 7.2 Agent 工具接口

| 工具名 | 参数 | 返回 |
|---|---|---|
| `search_knowledge` | `query: str` | 带 `[资料N | 来源]` 标注的文本块 |
| `calculate` | `expression: str` | 计算结果字符串 |

## 8. 部署架构

### 8.1 本地运行

```
浏览器 ──► FastAPI(127.0.0.1:8000) ──► DeepSeek / 硅基流动 API
                 │
                 └──► Chroma(data/vector_store)
```

### 8.2 Docker 部署

```
docker compose up -d
   └── 容器 ai-rag-agent
         ├── uvicorn app.api:app（端口 8000）
         └── 环境变量由 --env-file .env 注入
```

### 8.3 配置管理

关键配置项（`.env`）：

| 变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` | 对话模型密钥 |
| `DEEPSEEK_MODEL` | 对话模型名（deepseek-flash） |
| `DEEPSEEK_BASE_URL` | DeepSeek 接口地址 |
| `SILICONFLOW_API_KEY` | Embedding 密钥 |
| `SILICONFLOW_BASE_URL` | Embedding 接口地址 |
| `EMBEDDING_MODEL` | Embedding 模型名（BAAI/bge-m3） |

## 9. 非功能性设计

### 9.1 安全设计

- API Key 通过 `.env` 注入，`.gitignore` 排除敏感文件；
- `calculate` 工具正则白名单防代码注入。

### 9.2 容错设计

- `network.py` 打补丁失败不影响主流程（try/except 兜底）；
- LLM 调用失败支持重试（`chat.py` 中最多重试 3 次，指数退避）；
- Agent 工具执行异常被捕获并返回错误信息，不中断循环。

### 9.3 可扩展性设计

- 工具通过 `ALL_TOOLS` 列表管理，新增工具只需添加 `@tool` 函数并注册；
- 向量库与 Embedding 通过抽象封装，可平滑替换为 Milvus / 其他 embedding 模型。
