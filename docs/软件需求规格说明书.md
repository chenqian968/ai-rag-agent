## 1. 引言

### 1.1 编写目的

本文档旨在明确「AI 知识库问答 Agent」系统的功能需求、非功能需求与约束条件，作为后续概要设计、详细设计、编码实现与测试验收的统一依据。目标读者包括：项目开发者、测试人员、评审人员及潜在使用者。

### 1.2 项目背景

传统知识库问答系统多采用「固定流程」：用户提问 → 检索 → 生成，检索策略单一、无法自主决策。本项目基于 **RAG（检索增强生成）** 与 **AI Agent（ReAct 智能体）** 技术，构建一个可自主决策的垂直领域智能问答助手：Agent 能自行判断「是否需要检索知识库、检索几次、是否进行计算」，并支持多轮对话记忆与网页可视化操作。

### 1.3 术语与缩略语

| 术语 | 全称 / 说明 |
|---|---|
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| Agent | 智能体，能自主决策并调用工具的 AI 程序 |
| ReAct | Reasoning + Acting，推理与行动交替的 Agent 范式 |
| LLM | Large Language Model，大语言模型 |
| Embedding | 文本向量化，将文本映射为高维向量 |
| 向量库 | 存储文本向量并支持相似度检索的数据库（本项目用 Chroma） |
| Function Calling | 大模型的工具调用能力 |
| chunk | 文本块，长文档切分后的检索单元 |

### 1.4 参考资料

- 《RAG 检索不准？我的 4 个调优实践》（项目技术博客）
- LangChain / LangGraph / Chroma 官方文档

## 2. 项目概述

### 2.1 产品定位

一个面向垂直领域的**本地化知识库问答 Agent**，用户可以上传私有文档建立专属知识库，随后通过自然语言与 Agent 对话获取带引用来源的答案。目标岗位演示方向：大模型应用 / AI Agent 开发工程师。

### 2.2 目标与价值

1. 将私有文档转化为可检索的知识库，实现「用自然语言问私有资料」；
2. 相比普通 RAG 流水线，通过 Agent 实现「自主决策」，体现技术深度；
3. 回答可溯源（带 `[资料N]` 引用），抑制大模型幻觉；
4. 提供网页界面，降低使用门槛，便于演示与交付。

### 2.3 用户角色

| 角色 | 描述 | 主要操作 |
|---|---|---|
| 普通用户 | 知识库使用者 | 上传文档、提问、查看回答与引用、清空知识库 |
| 系统管理员 | 部署与运维人员 | 配置 API Key、启动服务、维护向量库 |

## 3. 功能需求

### 3.1 功能总览

系统功能划分为四大模块：文档管理、知识库构建、智能问答（Agent）、系统管理。

```
功能树：
AI 知识库问答 Agent
├── 文档管理
│   ├── 上传文档（PDF / Word / Markdown / TXT）
│   └── 文档格式校验
├── 知识库构建
│   ├── 文档加载与解析
│   ├── 文本分块（chunking）
│   ├── 向量化（Embedding）
│   └── 向量库持久化（Chroma）
├── 智能问答（Agent）
│   ├── 知识库检索工具（search_knowledge）
│   ├── 数学计算工具（calculate）
│   ├── ReAct 自主决策循环
│   ├── 多轮对话记忆
│   └── 引用溯源
└── 系统管理
    ├── 清空知识库
    ├── 健康检查
    └── 环境配置（API Key）
```

### 3.2 详细功能需求

#### FR-01 文档上传

- **描述**：用户通过网页界面上传文档文件。
- **输入**：单个文件，支持格式 `.pdf`、`.docx`、`.md`、`.txt`。
- **处理**：后端接收文件，保存至临时目录，完成加载、分块、向量化后入库。
- **输出**：返回导入结果（文件名、文本块数量）。
- **异常**：不支持的格式返回错误提示「不支持的文件类型」；导入失败返回 400 错误。

#### FR-02 文档加载与解析

- **描述**：按文件后缀选择对应加载器解析文档内容。
- **映射关系**：`.txt`/`.md` → TextLoader；`.pdf` → PyPDFLoader；`.docx` → Docx2txtLoader。
- **要求**：解析后为每个文档片段补充 `source`（来源文件名）元数据，用于引用溯源。

#### FR-03 文本分块

- **描述**：将长文档切分为适合检索的文本块。
- **参数**：`chunk_size=300`（每块最大字符数）、`chunk_overlap=30`（相邻块重叠字符数）。
- **切分策略**：递归字符切分，按「空行 → 列表项 → 单行 → 句号 → 分号 → 逗号 → 空格」优先级寻找自然边界，优先保证条目式知识点独立成块。

#### FR-04 向量化与入库

- **描述**：将文本块通过 Embedding 模型转为向量并存入 Chroma 向量库。
- **Embedding 模型**：硅基流动 `BAAI/bge-m3`（1024 维，中文语义效果好）。
- **存储**：本地持久化（`data/vector_store`），collection 名为 `knowledge_base`。

#### FR-05 知识库检索（search_knowledge 工具）

- **描述**：Agent 调用该工具，检索与问题最相关的文本块。
- **检索算法**：混合检索 = 语义相似度检索 + 关键词字面匹配兜底。
  - 语义检索：向量余弦相似度，返回 Top-K 候选；
  - 关键词兜底：提取查询中的硬关键词（英文缩写 + 中文 n-gram），按「关键词命中数」重排，命中越多越靠前。
- **参数**：`query`（检索问题或关键词）；`top_k` 默认 6。
- **输出**：带来源标注的文本块列表。

#### FR-06 数学计算（calculate 工具）

- **描述**：Agent 调用该工具执行精确数值计算。
- **输入**：数学表达式（仅支持数字与 `+ - * / ( ) %` 运算）。
- **安全约束**：通过正则白名单校验，拒绝任意代码执行。
- **输出**：计算结果或错误提示。

#### FR-07 ReAct 自主决策

- **描述**：Agent 通过 LangGraph 编排 ReAct 循环，自主决定「是否调用工具、调用哪个工具、是否继续」。
- **决策规则**（系统提示词约束）：
  - 涉及知识库内容 → 调用 `search_knowledge`（知识库主题动态变化，不预设领域）；
  - 涉及数值计算 → 调用 `calculate`；
  - 简单闲聊 → 直接回答。
- **循环终止**：当 AI 消息不再包含 `tool_calls` 时结束。

#### FR-08 多轮对话记忆

- **描述**：系统维护会话历史，支持追问与指代消解。
- **实现**：前端将历史消息随请求传回后端，后端拼入 Agent 状态。

#### FR-09 引用溯源

- **描述**：基于知识库作答时，回答末尾标注 `[资料1]`、`[资料2]` 等引用来源。
- **约束**：若检索结果为「未检索到相关内容」，须诚实告知「根据现有资料无法回答」，不得编造。

#### FR-10 清空知识库

- **描述**：删除向量库持久化目录，实现知识库重置。
- **约束**：不影响源文档文件。

#### FR-11 健康检查

- **描述**：提供 `/api/health` 接口返回服务状态。

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|---|---|
| 单文档导入 | 中等规模文档（<10MB）导入时间在可接受范围（首次含 embedding 调用） |
| 检索响应 | 演示数据量下检索时间 < 1s |
| 并发 | 单机部署，支持顺序请求即可（演示场景） |

### 4.2 安全需求

1. **密钥安全**：API Key 存放于 `.env`，不纳入版本控制（`.gitignore` 已排除）；
2. **计算安全**：`calculate` 工具采用正则白名单，杜绝任意代码执行；
3. **数据隔离**：向量库本地持久化，不上传私有文档内容。

### 4.3 可用性需求

1. 提供网页界面，支持文档上传、对话、清空等操作；
2. 错误提示友好（如未配置 Key、格式不支持等给出明确指引）。

### 4.4 可维护性与可移植性

1. 模块化分层设计，各模块职责单一（见概要设计）；
2. 提供 `Dockerfile` 与 `docker-compose.yml`，支持容器化一键部署；
3. 关键配置通过环境变量注入，便于切换模型与向量库。

### 4.5 网络兼容性

- 系统须在 IPv6 优先导致 DNS 解析失败的网络环境下正常连接模型 API（通过强制 IPv4 优先解决）。

| 方法 | 路径 | 说明 |

## 6. 约束与假设

### 6.1 约束

1. 运行环境：Python 3.11；
2. 依赖第三方大模型服务（DeepSeek）与 Embedding 服务（硅基流动），需有效 API Key；
3. 向量库采用 Chroma（本地轻量方案），生产可替换为 Milvus 等。

### 6.2 假设

1. 用户已获取 DeepSeek 与硅基流动的 API Key；
2. 演示场景数据量较小（数十个 chunk），全量取回重排的性能代价可接受。

---

## 7. 验收标准

1. 上传 PDF / Word / Markdown / TXT 文档后，界面提示导入成功并显示文本块数量；
2. 提问知识库相关问题，回答准确且带 `[资料N]` 引用；
3. 更换不同主题知识库后，检索仍能命中新主题（领域不写死）；
4. 中文自然语言问题（如「小个子显高的搭配思路」）能正确召回相关文档块；
5. 提问计算类问题，Agent 能自主调用计算工具并给出正确结果；
6. 多轮对话中，Agent 能理解上下文指代（如「它」）。
